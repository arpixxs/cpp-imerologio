# How a C++ Compiler Works

When you run:
```bash
g++ main.cpp -o main
```
it looks like one step, but internally it's **4 stages**.

```
Source Code (.cpp)
        │
        ▼
 1. Preprocessing
        │
        ▼
 2. Compilation (to Assembly)
        │
        ▼
 3. Assembly (to Object Code)
        │
        ▼
 4. Linking
        │
        ▼
 Final Executable
```

---

## Stage 1: Preprocessing

The **preprocessor** handles everything starting with `#`, before real compilation begins.

- `#include <iostream>` → copy-pastes the entire header file's content into your code.
- `#define PI 3.14` → replaces every `PI` in the code with `3.14` (plain text substitution).
- `#ifdef`, `#ifndef`, `#endif` → conditionally includes/excludes code.

Output: one big expanded file (still C++, just no `#` lines left).

```bash
g++ -E main.cpp -o main.i    # view preprocessed output
```

---

## Stage 2: Compilation

The **compiler** takes the preprocessed code and converts it to assembly through several steps:

1. **Lexical analysis** — breaks code into tokens: `int`, `x`, `=`, `5`, `;`
2. **Syntax analysis (parsing)** — checks grammar rules, builds a tree structure (AST) of the code.
3. **Semantic analysis** — checks meaning: correct types, declared variables, valid operations.
4. **Optimization** — improves the code (removes unused code, simplifies expressions).
5. **Code generation** — produces **assembly code** for your CPU (x86, ARM, etc.).

```bash
g++ -S main.cpp -o main.s    # view generated assembly
```

At this stage, if you misspell a variable or mismatch types, you get a **compiler error**.

---

## Stage 3: Assembly

The **assembler** converts assembly code into actual **machine code (binary)**, saved as an **object file** (`.o`).

This file contains:
- Compiled machine instructions
- Placeholders for anything defined outside this file (like `std::cout`, or a function in another `.cpp` file)

```bash
g++ -c main.cpp -o main.o    # produce object file
```

---

## Stage 4: Linking

The **linker** takes your object file(s) and combines them with:
- Other object files (if your project has multiple `.cpp` files)
- Library code (the actual implementation of things like `std::cout`, `std::vector`, etc.)

It resolves every placeholder — "where is the real code for this function?" — and joins everything into **one final executable**.

```bash
g++ main.o -o main    # link into executable
./main                 # run it
```

If linking fails, you'll see errors like:
```
undefined reference to `someFunction()`
```
This means: compiler understood the code fine, but the linker couldn't find where that function is actually implemented.

---

## Compiler Error vs Linker Error (important distinction)

| Compiler Error | Linker Error |
|---|---|
| Happens in Stage 2 | Happens in Stage 4 |
| Code is written wrong (syntax/type) | Code is correct, but something can't be found |
| e.g. missing semicolon, wrong type | e.g. `undefined reference to main()` |

---

## Quick Summary

```
.cpp  →  (preprocessor)  →  expanded code
      →  (compiler)       →  assembly (.s)
      →  (assembler)      →  object file (.o)
      →  (linker)         →  executable
```
