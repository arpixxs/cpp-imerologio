# C++ Header Files

## 1. What is a Header File?

A header file (`.h` or `.hpp`) is a file that contains **declarations** — function prototypes, class definitions, constants, macros — meant to be **shared across multiple `.cpp` files**.

It does NOT usually contain full function bodies (implementation); it just tells the compiler "this exists, here's its interface."

```cpp
// iostream is a header file — it declares std::cout, std::cin, etc.
#include <iostream>
```

---

## 2. Why Header Files Exist

Imagine a project with 10 `.cpp` files, and 5 of them need to use the same function `add()`. Without header files, you'd have to copy-paste the function declaration into every file — messy and error-prone.

Header files solve this: write the declaration **once** in a `.h` file, then `#include` it wherever needed.

**Benefits:**
- **Code reuse** — share declarations across files without duplication.
- **Separation of interface and implementation** — users of your code see *what* a function does, not necessarily *how*.
- **Faster compilation** — only recompile `.cpp` files that changed, not everything.
- **Organization** — keeps large projects manageable by splitting code logically.

---

## 3. Two Types of Includes

```cpp
#include <iostream>     // angle brackets: standard library headers
#include "myheader.h"   // quotes: your own project headers
```

| Syntax | Searches | Used For |
|---|---|---|
| `<header>` | Compiler's system include paths | Standard library (`iostream`, `vector`, `string`) |
| `"header.h"` | Current directory first, then system paths | Your own custom headers |

## 4. Creating Your Own Header File

**Step 1 — `math_utils.h` (the header — declarations only):**
```cpp
#ifndef MATH_UTILS_H
#define MATH_UTILS_H

int add(int a, int b);        // declaration only, no body
int subtract(int a, int b);

#endif
```

**Step 2 — `math_utils.cpp` (the implementation):**
```cpp
#include "math_utils.h"

int add(int a, int b) {
    return a + b;
}

int subtract(int a, int b) {
    return a - b;
}
```

**Step 3 — `main.cpp` (using it):**
```cpp
#include <iostream>
#include "math_utils.h"

int main() {
    std::cout << add(3, 4);        // 7
    std::cout << subtract(10, 4);  // 6
}
```

**Compiling multiple files together:**
```bash
g++ main.cpp math_utils.cpp -o main
./main
```

## 5. Include Guards — `#ifndef` / `#define` / `#endif`

```cpp
#ifndef MATH_UTILS_H
#define MATH_UTILS_H

// header content here

#endif
```

### Why This Is Needed

If a header gets `#include`d more than once in the same translation unit (which happens easily in larger projects with multiple headers including each other), the compiler sees the same declarations twice → **redefinition error**.

**How it works:**
1. `#ifndef MATH_UTILS_H` → "if `MATH_UTILS_H` is NOT yet defined..."
2. `#define MATH_UTILS_H` → immediately define it.
3. If the header is included again later, `#ifndef` fails (since it's now defined), so the compiler **skips the entire content** between it and `#endif`.

This guarantees the header's content is processed only **once** per compilation, no matter how many times it's included.

### Modern Alternative: `#pragma once`

```cpp
#pragma once

int add(int a, int b);
int subtract(int a, int b);
```

Does the same job as include guards, but shorter and less error-prone (no risk of typo-ing the guard name). Supported by all major compilers (g++, clang, MSVC), though technically not part of the official C++ standard.

## 6. What Happens During Preprocessing (Recap Connection)

Recall from the compiler notes: `#include` is handled entirely by the **preprocessor**, before real compilation starts. It literally does a **copy-paste**:

```cpp
#include "math_utils.h"
int main() { ... }
```

becomes (after preprocessing):
```cpp
// entire content of math_utils.h pasted here
int add(int a, int b);
int subtract(int a, int b);

int main() { ... }
```

This is exactly why include guards matter — without them, if `math_utils.h` got included twice (directly or indirectly through another header), you'd literally end up with the declarations pasted in twice.

## 7. Standard Library Headers You'll Use Often

| Header | Provides |
|---|---|
| `<iostream>` | `std::cout`, `std::cin`, `std::endl` |
| `<string>` | `std::string` and string functions |
| `<vector>` | `std::vector` (dynamic array) |
| `<cmath>` | Math functions: `sqrt()`, `pow()`, `abs()` |
| `<algorithm>` | `sort()`, `find()`, `max()`, `min()` |
| `<fstream>` | File input/output |
| `<map>` | `std::map` (key-value pairs) |
| `<cstdlib>` | General utilities: `rand()`, `exit()` |

## 8. Header Files vs Source Files — Clear Split

| Header File (`.h` / `.hpp`) | Source File (`.cpp`) |
|---|---|
| Declarations (interface) | Definitions (implementation) |
| Function prototypes, class definitions, constants | Actual function bodies |
| Shared/included by many files | Compiled once into an object file |
| Should NOT contain executable logic (mostly) | Contains the real logic |

**Note:** Class definitions in C++ are commonly written *fully* in header files (including inline member functions), since classes need their full structure visible wherever they're used — this is different from standalone functions.

```cpp
// student.h
#ifndef STUDENT_H
#define STUDENT_H
#include <string>

class Student {
private:
    std::string name;
    int marks;

public:
    Student(std::string n, int m) : name(n), marks(m) {}
    void display() {
        std::cout << name << ": " << marks << "\n";
    }
};

#endif
```

## 9. Common Errors Related to Headers

| Error | Cause |
|---|---|
| `redefinition of 'X'` | Missing include guards / `#pragma once` |
| `undefined reference to 'add(int, int)'` | Declared in header, but never defined in any `.cpp`, or `.cpp` not linked |
| `fatal error: myheader.h: No such file or directory` | Wrong path, or used `<>` instead of `""` for a local header |
| `X does not name a type` | Forgot to `#include` the header that defines that type |

## Quick Reference Summary

| Concept | Key Idea |
|---|---|
| Header file | Declarations shared across files |
| `#include <>` | For standard library headers |
| `#include ""` | For your own project headers |
| Include guards | Prevent duplicate inclusion errors |
| `#pragma once` | Modern shortcut for include guards |
| Preprocessor | Physically copy-pastes header content before compiling |
