# C++ Functions — Deep Notes

## 1. What is a Function?

A function is a **named, reusable block of code** that performs a specific task. Instead of repeating the same logic everywhere, you write it once and *call* it whenever needed.

```cpp
#include <iostream>

int add(int a, int b) {      // function definition
    return a + b;
}

int main() {
    int result = add(3, 4);   // function call
    std::cout << result;      // 7
}
```

### Why Use Functions?
- **Reusability** — write once, use many times.
- **Readability** — breaks big problems into smaller, named pieces.
- **Maintainability** — fix a bug in one place, not everywhere.
- **Abstraction** — you don't need to know *how* `add()` works internally to use it.

---

## 2. Anatomy of a Function

```cpp
returnType functionName(parameterType parameterName, ...) {
    // function body
    return value;   // only if returnType is not void
}
```

| Part | Meaning |
|---|---|
| `returnType` | The data type of the value the function sends back (`int`, `double`, `void`, etc.) |
| `functionName` | Identifier used to call the function |
| `parameters` | Inputs the function accepts (also called **arguments** when passed in a call) |
| `body` | The actual code that runs |
| `return` | Sends a value back to the caller and exits the function |

---

## 3. Function Declaration vs Definition

C++ reads code top to bottom. If you call a function *before* it's written in the file, you need to **declare** it first (a prototype), then define it later.

```cpp
#include <iostream>

int add(int a, int b);   // DECLARATION (prototype) — tells compiler it exists

int main() {
    std::cout << add(2, 3);   // works, even though defined below
}

int add(int a, int b) {   // DEFINITION — actual body
    return a + b;
}
```

- **Declaration**: tells the compiler "this function exists, here's its signature" — no body.
- **Definition**: the actual implementation.

This matters directly because of how the compiler works: it processes files top-to-bottom in a single pass, so it needs to know a function exists before it's called.

## 4. `void` Functions (No Return Value)

```cpp
void greet(std::string name) {
    std::cout << "Hello, " << name << "!\n";
    // no return needed
}

int main() {
    greet("Aisha");   // prints: Hello, Aisha!
}
```

`void` means the function performs an action but doesn't send any value back.

## 5. Parameters: Pass by Value vs Pass by Reference vs Pass by Pointer

This is one of the most important concepts in C++ functions.

### a) Pass by Value (default) — makes a COPY

```cpp
void increment(int x) {
    x = x + 1;          // modifies the COPY only
}

int main() {
    int num = 5;
    increment(num);
    std::cout << num;   // still 5 — original unchanged
}
```

The function receives a **copy** of the variable. Changes inside the function do NOT affect the original.

### b) Pass by Reference — modifies the ORIGINAL

```cpp
void increment(int& x) {   // & means reference
    x = x + 1;
}

int main() {
    int num = 5;
    increment(num);
    std::cout << num;   // 6 — original changed!
}
```

Using `&` in the parameter means `x` is an **alias** for the original variable — no copy is made, and changes affect the caller's variable directly.

### c) Pass by Pointer — pass the ADDRESS

```cpp
void increment(int* x) {
    *x = *x + 1;   // dereference to modify original value
}

int main() {
    int num = 5;
    increment(&num);   // pass address of num
    std::cout << num;  // 6
}
```

Similar effect to reference, but more explicit — you're passing a memory address, and must dereference (`*`) to access/modify the value.

### Comparison Table

| Method | Syntax | Copies Data? | Can Modify Original? | Can Be Null? |
|---|---|---|---|---|
| Pass by value | `void f(int x)` | Yes | No | N/A |
| Pass by reference | `void f(int& x)` | No | Yes | No |
| Pass by pointer | `void f(int* x)` | No | Yes | Yes |

**Why it matters for memory:** pass by value copies the full size of the data — expensive for large objects (like big structs, vectors, strings). Pass by reference avoids the copy entirely, which is why large objects are often passed as `const Type&` to avoid both copying AND accidental modification:

```cpp
void printName(const std::string& name) {   // no copy, cannot modify
    std::cout << name;
}
```

## 6. Default Arguments

```cpp
void greet(std::string name = "Guest") {
    std::cout << "Hello, " << name << "!\n";
}

int main() {
    greet();          // Hello, Guest!
    greet("Zara");     // Hello, Zara!
}
```

If no argument is passed, the default value is used. Default parameters must come **after** non-default ones:
```cpp
void f(int a, int b = 10);   // OK
void f(int a = 10, int b);   // ERROR
```

## 7. Function Overloading

C++ allows multiple functions with the **same name** but **different parameter types/counts** — the compiler picks the right one based on the arguments.

```cpp
int add(int a, int b) {
    return a + b;
}

double add(double a, double b) {
    return a + b;
}

int add(int a, int b, int c) {
    return a + b + c;
}

int main() {
    std::cout << add(2, 3);        // calls int version → 5
    std::cout << add(2.5, 3.5);    // calls double version → 6.0
    std::cout << add(1, 2, 3);     // calls 3-param version → 6
}
```

This is resolved at **compile time** based on the function signature (name + parameter types/count) — this is called **compile-time polymorphism**.

## 8. Recursion (Function Calling Itself)

```cpp
int factorial(int n) {
    if (n <= 1) {
        return 1;         // base case — stops recursion
    }
    return n * factorial(n - 1);   // recursive case
}

int main() {
    std::cout << factorial(5);   // 120
}
```

How it works internally:
```
factorial(5)
= 5 * factorial(4)
= 5 * (4 * factorial(3))
= 5 * (4 * (3 * factorial(2)))
= 5 * (4 * (3 * (2 * factorial(1))))
= 5 * 4 * 3 * 2 * 1
= 120
```

Each call is pushed onto the **call stack**. Without a base case, this causes infinite recursion → **stack overflow**.

---

## 9. Inline Functions

```cpp
inline int square(int x) {
    return x * x;
}
```

`inline` is a *suggestion* to the compiler to replace the function call with the actual code directly (avoiding call overhead) — useful for small, frequently-called functions. The compiler may ignore this hint if it decides otherwise.

---

## 10. Function Scope and Lifetime

```cpp
int add(int a, int b) {
    int sum = a + b;   // local variable — lives only inside this function
    return sum;
}
// 'sum', 'a', 'b' no longer exist here — destroyed when function ends
```

Local variables are created on the **stack** when the function is called, and destroyed automatically when the function returns.

## 11. Returning Multiple Values (via reference or struct)

C++ functions can only directly `return` one value, but you can work around this:

```cpp
#include <iostream>

void getMinMax(int arr[], int size, int& minOut, int& maxOut) {
    minOut = arr[0];
    maxOut = arr[0];
    for (int i = 1; i < size; i++) {
        if (arr[i] < minOut) minOut = arr[i];
        if (arr[i] > maxOut) maxOut = arr[i];
    }
}

int main() {
    int arr[] = {5, 2, 9, 1, 7};
    int minVal, maxVal;
    getMinMax(arr, 5, minVal, maxVal);
    std::cout << "Min: " << minVal << ", Max: " << maxVal;
}
```

## 12. Function Call Stack — What Actually Happens in Memory

When `main()` calls `add(3, 4)`:

1. A new **stack frame** is created for `add()`.
2. Parameters (`a=3`, `b=4`) and local variables are stored in that frame.
3. The function executes.
4. The `return` value is sent back.
5. The stack frame is **popped (destroyed)** — all its local variables are gone.
6. Control returns to `main()` at the line right after the call.

```
Call Stack (grows downward):
┌─────────────────┐
│   add(3, 4)      │ ← currently executing
├─────────────────┤
│   main()         │ ← waiting for add() to finish
└─────────────────┘
```

This is also why recursion without a base case crashes — every call adds a new frame, and the stack has limited size.

## Quick Reference Summary

| Concept | Key Idea |
|---|---|
| Declaration | Signature only, no body |
| Definition | Actual implementation |
| Pass by value | Copies data, original unaffected |
| Pass by reference | No copy, original CAN change |
| Pass by pointer | Address passed, needs dereferencing |
| Default arguments | Fallback values if not passed |
| Overloading | Same name, different parameters |
| Recursion | Function calling itself, needs base case |
| Inline | Suggests replacing call with code directly |
