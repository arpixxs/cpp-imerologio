# Debugging C++ in VS Code 

## 1. What is Debugging?

Debugging is the process of **stepping through your running program** to inspect variables, control flow, and memory — instead of just guessing what went wrong from `cout` statements. A debugger lets you pause execution, look inside, and move forward one step at a time.

---

## 2. Prerequisites (Setup Rules)

To debug C++ in VS Code, you need:

1. **VS Code** installed.
2. **C/C++ Extension** by Microsoft (from Extensions marketplace — search "C/C++").
3. **A working compiler**:
   - Windows → MinGW (g++) or MSVC
   - Linux → g++ (usually pre-installed, else `sudo apt install g++`)
   - macOS → Xcode Command Line Tools (`xcode-select --install`)
4. Verify compiler is installed and in PATH:
```bash
g++ --version
```
If this doesn't show a version, VS Code cannot debug — fix your PATH/install first.

## 3. Project Folder Structure

```
my_project/
│
├── main.cpp
└── .vscode/
    ├── launch.json      ← how to START debugging
    ├── tasks.json        ← how to BUILD (compile) the program
    └── c_cpp_properties.json   ← compiler path & IntelliSense config (optional but helpful)
```

VS Code auto-generates these when you first configure debugging through the UI, but you can also write them manually.

---

## 4. `tasks.json` — The Build Step

Debugging needs a compiled executable with **debug symbols** included. This file tells VS Code *how to compile*.

```json
{
    "tasks": [
        {
            "type": "cppbuild",
            "label": "C/C++: g++ build active file",
            "command": "g++",
            "args": [
                "-g",                       // IMPORTANT: includes debug info
                "${file}",
                "-o",
                "${fileDirname}/${fileBasenameNoExtension}"
            ],
            "options": {
                "cwd": "${fileDirname}"
            },
            "group": {
                "kind": "build",
                "isDefault": true
            }
        }
    ],
    "version": "2.0.0"
}
```

**Key rule:** the `-g` flag is mandatory. Without it, the debugger has no line/variable mapping and can't step through source code meaningfully.

---

## 5. `launch.json` — The Debug Step

This tells VS Code *how to run the debugger* once the program is built.

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "g++ - Debug",
            "type": "cppdbg",
            "request": "launch",
            "program": "${fileDirname}/${fileBasenameNoExtension}",
            "args": [],
            "stopAtEntry": false,
            "cwd": "${fileDirname}",
            "environment": [],
            "externalConsole": false,
            "MIMode": "gdb",              // debugger backend (lldb on macOS)
            "setupCommands": [
                {
                    "description": "Enable pretty-printing for gdb",
                    "text": "-enable-pretty-printing",
                    "ignoreFailures": true
                }
            ],
            "preLaunchTask": "C/C++: g++ build active file"
        }
    ]
}
```

- `"program"` → path to the compiled executable.
- `"preLaunchTask"` → automatically runs the build (tasks.json) before debugging starts.
- `"MIMode": "gdb"` → uses GDB debugger (Linux/Windows-MinGW). On macOS this is usually `"lldb"`.

## 6. Core Debugging Concepts (Rules to Know)

| Concept | Meaning |
|---|---|
| **Breakpoint** | A marker on a line that pauses execution when reached. Click left of the line number (red dot). |
| **Step Over (F10)** | Runs the current line, does NOT go inside function calls on that line. |
| **Step Into (F11)** | Goes INSIDE a function call to debug it line-by-line. |
| **Step Out (Shift+F11)** | Finishes the current function and returns to the caller. |
| **Continue (F5)** | Runs until the next breakpoint or program end. |
| **Watch** | Add a variable/expression to track its value as you step. |
| **Call Stack panel** | Shows the chain of function calls that got you to the current line. |
| **Variables panel** | Shows all local variables and their current values at the paused line. |

## 7. Solved Example — Debugging a Buggy Program

**Buggy code (`main.cpp`):**
```cpp
#include <iostream>
using namespace std;

int factorial(int n) {
    int result = 0;        // BUG: should start at 1, not 0
    for (int i = 1; i <= n; i++) {
        result = result * i;
    }
    return result;
}

int main() {
    int num = 5;
    int ans = factorial(num);
    cout << "Factorial of " << num << " is " << ans << endl;
    return 0;
}
```

**Expected output:** `Factorial of 5 is 120`
**Actual output:** `Factorial of 5 is 0` ← something's wrong

### Step-by-step debugging process:

**Step 1 — Set a breakpoint**
Click to the left of the line `int result = 0;` — a red dot appears.

**Step 2 — Start debugging**
Press `F5`. VS Code builds the program (via `tasks.json`) and pauses execution at your breakpoint.

**Step 3 — Inspect variables**
Look at the **Variables panel** (left side). You'll see:
```
n = 5
```
Correct so far — `n` was passed properly.

**Step 4 — Step over line by line (F10)**
- After `int result = 0;` executes → Variables panel shows `result = 0`.
- Enter the loop: `i = 1`.
- Step over `result = result * i;` → Variables panel shows `result = 0` (since `0 * 1 = 0`).
- Continue stepping (`F10`) through more iterations → `result` stays `0` forever, because anything multiplied by `0` is `0`.

**Step 5 — Found the bug**
The Variables panel makes it obvious: `result` never leaves `0`. The issue is the **initial value**. It should be `1` (the multiplicative identity), not `0`.

**Step 6 — Fix the code**
```cpp
int factorial(int n) {
    int result = 1;         // FIXED
    for (int i = 1; i <= n; i++) {
        result = result * i;
    }
    return result;
}
```

**Step 7 — Re-run debugger to confirm**
Set the same breakpoint, step through again:
```
result = 1   (initial)
i=1 → result = 1
i=2 → result = 2
i=3 → result = 6
i=4 → result = 24
i=5 → result = 120
```
Matches expected output: `Factorial of 5 is 120` ✅

## 8. Using Watch & Call Stack (Extra Practice on Same Example)

- Add `result` and `i` to the **Watch panel** manually — this lets you track them without checking the Variables panel every time.
- Open **Call Stack panel** while paused inside `factorial()` — you'll see:
```
factorial(int)   ← currently here
main()           ← called factorial()
```
This confirms exactly *how* you got to the current line — very useful in larger programs with many function calls.

---

## 9. Conditional Breakpoints (Advanced Rule)

Right-click a breakpoint → **Edit Breakpoint** → add a condition:
```cpp
i == 3
```
The debugger will only pause when `i` equals `3`, instead of stopping on every loop iteration. Extremely useful for bugs that only happen deep into a loop or on a specific condition.

---

## 10. Common Debugging Errors in VS Code (Setup Issues)

| Problem | Fix |
|---|---|
| "Unable to start debugging. Executable does not exist" | Build task failed or wrong path in `launch.json` → check `program` field |
| Debugger doesn't stop at breakpoints | Missing `-g` flag in `tasks.json` |
| "GDB not found" | Compiler/debugger not installed or not in PATH |
| Breakpoints show as hollow/greyed circles | Program wasn't compiled with debug symbols, or source doesn't match binary — rebuild |
