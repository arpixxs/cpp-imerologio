# C++ Variables & Memory

## 1. What is a Variable?

A variable is a **named location in memory (RAM)** that holds a value. When you write:

```cpp
int age = 21;
```

what actually happens:
1. The compiler reserves **4 bytes** of memory (size of `int`).
2. That memory location gets a **name** (`age`) that you can refer to.
3. The value `21` is stored in that memory in **binary form**.
4. `age` now has an **address** (where it lives in RAM) and a **value** (what's stored there).

You can see the address using the `&` operator:
```cpp
std::cout << &age;   // prints the memory address of age
```

---

## 2. How Memory is Organized (Bit → Byte → Word)

- **Bit** — smallest unit, holds `0` or `1`.
- **Byte** — 8 bits grouped together. This is the smallest *addressable* unit of memory (each byte has its own address).
- **Word** — group of bytes the CPU processes at once (commonly 4 or 8 bytes on modern 32-bit/64-bit systems).

```
1 byte  = 8 bits
1 KB    = 1024 bytes
1 MB    = 1024 KB
```

A variable's **size** tells you how many bytes it occupies, which directly determines:
- The **range of values** it can store
- How much memory your program uses
- How fast operations on it can be (smaller types are usually faster to move/copy)

## 3. Fundamental Data Types & Their Byte Sizes

> Sizes below are **typical on a 64-bit system (most common today, e.g. g++ on 64-bit Linux/Windows)**. C++ standard does NOT fix exact sizes — it only guarantees minimum ranges. Always confirm with `sizeof()` on your own machine.

| Type | Typical Size | Range (typical) | Notes |
|---|---|---|---|
| `bool` | 1 byte | `true` (1) / `false` (0) | Only technically needs 1 bit, but uses 1 byte because that's the smallest addressable unit |
| `char` | 1 byte | -128 to 127 (signed) or 0 to 255 (unsigned) | Stores a single character using ASCII code |
| `unsigned char` | 1 byte | 0 to 255 | No negative values |
| `short` (short int) | 2 bytes | -32,768 to 32,767 | Smaller integer range |
| `unsigned short` | 2 bytes | 0 to 65,535 | |
| `int` | 4 bytes | -2,147,483,648 to 2,147,483,647 (~-2.1B to 2.1B) | Default integer type |
| `unsigned int` | 4 bytes | 0 to 4,294,967,295 | |
| `long` | 4 or 8 bytes (compiler dependent) | at least -2.1B to 2.1B, often much larger | On most 64-bit Linux systems: 8 bytes |
| `unsigned long` | 4 or 8 bytes | 0 to very large | |
| `long long` | 8 bytes | ~-9.2 quintillion to 9.2 quintillion | Guaranteed at least 8 bytes since C++11 |
| `unsigned long long` | 8 bytes | 0 to ~18.4 quintillion | |
| `float` | 4 bytes | ~±3.4 × 10³⁸ (7 decimal digits precision) | Single-precision floating point |
| `double` | 8 bytes | ~±1.7 × 10³⁰⁸ (15 decimal digits precision) | Double-precision, default for decimals |
| `long double` | 8, 12, or 16 bytes (compiler dependent) | Even larger range/precision | Rarely needed unless extreme precision required |
| `wchar_t` | 2 or 4 bytes | Depends on platform | Wide character (Unicode support) |

You can always verify on YOUR system with:
```cpp
#include <iostream>
int main() {
    std::cout << "bool: " << sizeof(bool) << " byte(s)\n";
    std::cout << "char: " << sizeof(char) << " byte(s)\n";
    std::cout << "short: " << sizeof(short) << " byte(s)\n";
    std::cout << "int: " << sizeof(int) << " byte(s)\n";
    std::cout << "long: " << sizeof(long) << " byte(s)\n";
    std::cout << "long long: " << sizeof(long long) << " byte(s)\n";
    std::cout << "float: " << sizeof(float) << " byte(s)\n";
    std::cout << "double: " << sizeof(double) << " byte(s)\n";
    std::cout << "long double: " << sizeof(long double) << " byte(s)\n";
}
```

## 4. Why `int` is 4 Bytes — What That Actually Means

4 bytes = 32 bits. Each bit can be `0` or `1`, so total combinations = 2³² = 4,294,967,296 possible values.

For a **signed int** (can hold negative numbers), one bit is used as the sign bit, splitting the range roughly in half:
```
Range = -2^31 to (2^31 - 1)
      = -2,147,483,648 to 2,147,483,647
```

For **unsigned int** (no negatives), all 32 bits go toward magnitude:
```
Range = 0 to (2^32 - 1)
      = 0 to 4,294,967,295
```

This pattern (one bit reserved for sign in signed types) applies to every signed/unsigned pair.

## 5. `char` in Detail

```cpp
char grade = 'A';
```

- Internally, `'A'` is NOT stored as the letter — it's stored as a **number** (ASCII code 65).
- 1 byte = 8 bits = can represent 256 distinct values → maps perfectly to the ASCII table (0–255).
- You can literally do math with a `char`:
```cpp
char c = 'A';
std::cout << (int)c;      // prints 65
std::cout << c + 1;        // prints 66 (as int, due to promotion)
char next = c + 1;
std::cout << next;         // prints 'B'
```

## 6. Floating Point Storage (float vs double) — Why They're Different

Floating point numbers are NOT stored the same way integers are. They use the **IEEE 754 standard**, splitting bits into 3 parts:

```
[ Sign bit ] [ Exponent bits ] [ Mantissa/Fraction bits ]
```

| Type | Total bits | Sign | Exponent | Mantissa |
|---|---|---|---|---|
| float | 32 | 1 | 8 | 23 |
| double | 64 | 1 | 11 | 52 |

This is WHY `double` has more precision than `float` — more mantissa bits = more accurate decimal digits stored.

⚠️ Because of this binary representation, floating point math can have rounding errors:
```cpp
float x = 0.1f + 0.2f;
std::cout << x;   // might print 0.30000001, not exactly 0.3
```

## 7. Where Variables Live in Memory: Stack vs Heap

| Stack | Heap |
|---|---|
| Automatic, fast allocation | Manual allocation (`new`) |
| Memory freed automatically when scope ends | Must be freed manually (`delete`) or leaks |
| Fixed size, limited (can overflow with deep recursion) | Large, flexible size |
| Used for normal local variables | Used for dynamically-sized/long-lived data |

```cpp
void example() {
    int x = 10;              // stored on the STACK
    int* p = new int(20);    // 20 is stored on the HEAP; p (pointer) is on the stack
    delete p;                 // must manually free heap memory
}
// x is automatically destroyed when example() ends
```

If you forget `delete`, that heap memory stays reserved forever (until program ends) — this is a **memory leak**.

---

## 8. `sizeof()` — Your Best Tool to Verify Memory Usage

```cpp
int a = 5;
std::cout << sizeof(a);       // 4 (bytes)
std::cout << sizeof(int);      // 4
std::cout << sizeof(a) * 8;    // 32 (bits)
```

`sizeof()` works on variables, types, and even expressions — always returns size **in bytes**.

---

## 9. Signed vs Unsigned — Deep Note

```cpp
unsigned int x = -1;
std::cout << x;   // prints 4294967295, NOT -1!
```

Why? Unsigned types have no sign bit — if you assign a negative number, it **wraps around** (this is called **integer overflow/underflow behavior**), using all 32 bits as pure magnitude. This is a common bug source — be careful mixing signed and unsigned types.
